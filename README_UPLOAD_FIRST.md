# Alpha Radar V19.1｜部署與使用說明

本版依使用者提供的V19.0歷史報告修正「調權選擇流程、報酬可比性、缺值處理和投資狀態呈現」。不是宣稱重新訓練出全市場最佳權重，也沒有重新跑出原92個代碼的真實績效。版本：19.1.0。

## 1. 安裝

完整部署包：解壓後，把全部檔案放入GitHub專案根目錄，覆蓋同名檔案；不要把ZIP當成Streamlit啟動檔。啟動檔仍為`app.py`。

精簡更新包：只適用於完整V19.0（原58檔）專案，全部覆蓋，不要只換`app.py`。保留原有`data/`、SQLite、`.streamlit/secrets.toml`和Secrets；本包不包含私人Token。

安裝套件依原`requirements.txt`。本版沒有新增付費行情的必要權限，也沒有新增大型機器學習依賴。資料來源仍受其可用性與使用條件限制。

## 2. 第一次重跑

進入「歷史驗證」，先採近3年、100檔、10個基準日、5／20／60日、24組候選。勾選「沿用附件10個日期（開發重播）」；為對照附件，資料截止日使用2026-10-15。

先關閉基本面／籌碼選配，釐清同一技術模型的資料與驗證差異，再另開一輪比較有公告時點的選配資料。新版會真的遵守這個開關，不會關閉後仍讀入既有選配快取。

「下載近年資料＋執行驗證」會優先嘗試同來源一致的還原價，再回退可用日線。這可能使結果不同於V19.0原始未還原價報告；請查看來源與價格基礎，不能把資料口徑修正全部歸功於因子效果。

「只用快取執行驗證」適合先重播原有資料、避免重複下載。不過快取若只有未還原價，本次仍不會憑空產生還原價。各組別會記錄RAW_PRICE_ONLY／ADJUSTED_PROVIDER等狀態。

研究股票池若重新下載，可能與附件原92個代碼不同。原池及原股價輸入不在這份Markdown內，所以無法只憑該檔保證完全一致。

## 3. 調權的改變

原因子組與起始權重保留：趨勢、相對強度、突破、反轉、W底／頸線型態、量能；有足夠時點資料再加入營收、品質、外資、投信、同步買超、自營商自行買賣、融資與大戶。

V19.1不是直接提高KD或降低營收的固定係數，而是修正權重取得方式：
- 每個5／20／60日週期獨立計算。
- 只使用基準日前已經結束的持有期結果。
- 訓練樣本和內部驗證樣本間排除持有區間交疊。
- 訓練階段選出一個挑戰權重；內部驗證只作通過／不通過，不再於驗證區挑選多個試算中的冠軍。
- 改動先收縮50%回原權重，而且直接驗證收縮後的權重，不是測完才偷改。
- 使用至少4段不重疊驗證區塊，並要求同日期、同價格基礎比較。候選改善不能只靠一個大贏家；要兼顧多數區塊、成本後報酬、0050、路徑風險及假設成交率。
- 不足以證明改善就保留起始權重，明示原因，不把「跑完」稱為「最佳化完成」。

4段、50%、改善0.2個百分點等都是預先訂定的研究治理門檻，不是附件證明的最佳參數，也不代表足以建立統計顯著性。

## 4. 怎麼看畫面

研究排名回答「先研究哪檔」，不是「現在一定要買」。畫面會把是否有過去驗證支持、資料是否完整、買賣訊號是否可用分開。

「固定權重」是V19.1同一資料處理下的起始係數；「自適應」是經內部驗證程序選出的研究係數。它們不是Gemini或V18的重建績效。

新加的「證據不足留現金」是另一條事先定義的模擬政策：在基準日前缺乏優於0050的證據時保持現金，現金利息假設為0。它不會把自適應策略的虧損或缺值改成0；原策略結果仍保留。亦不會自動下單或自動替你買入0050。

與0050比較時使用雙方相同日期且價格基礎相容的樣本，列出分母。報告中的平均是各基準日報酬算術平均，不是連續投入同一資金的累積報酬或年化報酬。

## 5. 資料不足如何呈現

- 進場價格缺失：未能驗證，績效留空，不視為免費持有現金。
- 事先規定的無量、開高過多或一價鎖定：依既定假設不進場，記錄具體原因。
- 進出場端點有效、中間缺日線：可算固定持有期端點報酬，但MAE／MFE／最大回撤留空，不能假設途中沒有風險。
- 出場價格缺失或公司行動不能核對：結果仍留空，不刪掉該檔改用其他股票。
- 股票分割、還原價缺段：區分可比較與不確定資料，不跨來源硬接。
- 0050沒有資料：保留模型結果；相對0050欄位留空，並明示缺漏原因。
- 0050作為被動比較基準，不再套用主動個股的4%開高追價上限。這是新舊基準定義差異，須一併閱讀。
- 分類篩選先在整個已下載且符合條件的股票池執行，再取前幾名，不限於全體前20名中挑同類股票。
- 即時價與歷史回測仍分層。本版不是分鐘反轉或實際漲停命中的驗證。

## 6. 下載完整驗證診斷包

跑完後，在歷史驗證頁按「下載完整驗證診斷包（含股價與權重）」。ZIP包含：
原始輸入股價與選配資料、來源清單、完整設定、每次推薦和進出場價、各因子分數及權重、候選訓練與驗證軌跡、缺資料逐檔清單、同日期績效表及可讀報告。

只有Markdown摘要不足以解釋哪個因子造成虧損。完整包可直接重播相同資料，不必再向網路重新抓一套不同股票池。匯出不包含Secrets或API Token；但股價／研究結果是你的資料，分享前仍應自行確認。

## 7. 命令列

使用既有快取與附件原10日期：
```bash
python run_v19.py --cache-only --years 3 --stocks 100 --as-of 2026-10-15 --reference-report reference_validation_v190.md
```

下載資料後執行：
```bash
python run_v19.py --years 3 --stocks 100 --as-of 2026-10-15 --reference-report reference_validation_v190.md
```

讀取新版匯出的完整診斷包重播：
```bash
python run_v19.py --replay-bundle v191_diagnostic_bundle.zip --as-of 2026-10-15 --reference-report reference_validation_v190.md
```

只重算附件摘要數字，不下載行情或調權：
```bash
python v191_audit.py reference_validation_v190.md --output supplied_report_audit
```

程式驗證（pytest只在自行測試時安裝，不是網站啟動必要套件）：
```bash
python -m pip install pytest
python -m compileall -q .
python -m pytest -q
```

## 8. 驗證界線

附件十個基準日已用於檢討V19.1設計，重跑只能叫開發重播，不能再稱完全未見過的新樣本外驗證。新門檻及係數要在另行凍結且尚未檢視的資料／未來記錄驗證。

這次修改不是把已輸給0050的20／60日結果消掉，也不是用測試期挑出最賺的一組權重。真實新版績效仍待以完整原資料重播。程式測試、UI模擬及運算效能測試，均不能替代Streamlit Cloud正式環境或真實交易驗證。
